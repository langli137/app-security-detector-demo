上架可能性：很低（当前不可上架） 功能实现：后端检测可用（已修复 1 个缺陷）

这是一个 “移动应用安全检测 Demo”：Android 客户端（Jetpack Compose）选择 APK/ZIP → 上传到 FastAPI 后端 → 后端执行静态规则检测或多 Agent 分析 → 返回安全评分、风险等级与修复建议。经实测，核心检测功能在后端可用且结果正确；但作为可上架的应用，存在多处必须修复的硬性阻塞（硬编码模拟器后端地址、Demo 命名、缺少隐私政策与签名配置等）。

1. 项目架构概览

android-clientCompose 客户端：上传文件、轮询进度、展示报告（调用 /api/upload · /api/tasks/{id} · /api/reports/{id}） backendFastAPI 服务：两套引擎 —— rules（正则/关键字静态扫描）与 agent（6 个 Agent 流水线 + 修复/合规建议） miniappTaro 小程序前端（独立入口） samples示例源码，用于演示被检应用

关键事实：Android 客户端是纯前端壳，所有检测逻辑都在后端。客户端硬编码后端地址 BASE_URL = "http://10.0.2.2:8000/"（Android 模拟器本机回环），在真机或上架后无法访问任何后端。

3.3 测试中发现并修复的缺陷

缺陷：agent 引擎经 API 调用时报 KeyError('high')，任务状态变 failed；但单元测试 test_agents.py 却能跑通（因为它不渲染 HTML）。

根因：render_html() 用 s['high']（小写键）读取 summary，而 agent 引擎写入的是大写键（High/Medium…）；rules 引擎写小写键故正常。键名不一致导致渲染时 KeyError。

修复：① 在 run_scan_agent 中将 agent 的 summary 归一化为小写键，与 rules 引擎及 Android 客户端 RiskSummary 数据模型一致；② 让 render_html 兼容大小写键。修复后两端报告 JSON/HTML 均正常生成。

✅ 已修复并复测通过。

4. 结论与建议

上架可能性：当前很低，基本不可上架。主要 blockers 为硬编码模拟器后端、Demo 命名、缺隐私政策与签名配置——均为“能否过审”的硬性条件，而非能力问题。

功能实现：已验证可用。后端两套检测引擎均能正确分析样本 APK/ZIP，产出评分、风险等级、详细发现与修复/合规建议；客户端代码逻辑完整正确，唯一使其“装不上/用不了”的原因是后端不可达，而非代码缺陷。

建议路线：若希望真正上架，按第 2 节清单改造（可配置 HTTPS 后端 + 托管服务 + 隐私政策 + 正式命名 + 签名）；当前代码是一个完成度高、可演示的原型，适合作为课程/毕设/内部工具使用。

本报告基于项目源码静态审查与后端 API 端到端实测生成。Android 客户端因依赖模拟器/真机与后端，未做 APK 编译运行，但其调用逻辑已通过等效 API 测试间接验证。
